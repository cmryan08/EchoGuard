# Hands-free room calibration and sitting/standing tracker (v1)

EchoGuard moves from fall detection to a sitting/standing time tracker. One Start click runs a hands-free calibration on a timed schedule: leave the room, empty room recorded, come back in, walk, stand still, sit. The UI beeps and speaks at every phase. The recorded per-subcarrier amplitude profiles train a per-room diagonal-Gaussian sitting/standing/empty model. A live classifier with hysteresis feeds a tracker that records bouts, sitting streaks, stand reminders and stand hours. History goes to SQLite, but only for live, non-synthetic sources. `make test` passes (2 skipped) and `node --check` passes. A shortened HTTP calibration run on the `desk_day` simulation completed all four steps, computed, saved under a `__synthetic` key, and the Today endpoint then reported a calibrated posture. The default plan computes to 0:00 / 0:05 / 0:26 / 0:31 / 0:47 / 0:50 / 1:11 / 1:14, 1:35 total, as specified. Nothing has been run against real hardware.

Watch for: fidgeting while seated can count as "moving", and moving counts as upright (likely, non-blocking). Calibration activity is written into the user's history (confirmed, minor). The schedule table is hidden during the run (confirmed, cosmetic).

## High-level view

The calibration timeline is computed once on the server (`build_timeline`), fixed when Start is pressed, and mirrored in JS for the pre-run plan. Waits (lead-in, grace, transition) run on the wall clock. Recorded steps run on packet time, and each step drops its first `settle_s` (= `window_s`, 1 s) so the analysis window clears. That is why each 20 s step shows as 21 s. A failed step stops the run and leaves a "Continue" path that resumes from the failed step with a "Get ready" lead-in.

The posture model selects the 16 subcarriers with the best sitting-vs-standing Fisher score. It is checked with a temporal half-split self-check that the code and UI label as optimistic and not validated. When separation is weak, the result carries a placement warning instead of failing. When the model cannot be fitted, the calibration still saves with thresholds only, and the Today page says to recalibrate. The live classifier never reports sitting or standing without a model.

Live state reaches the Today page through `/api/posture`, polled every 2 s. The page shows the hysteresis state, the confidence, the streak or how long the current state has lasted, and today's tiles. Readings older than 5 s turn into "unknown". The UI is system-font, gradient-free and makes no network calls. The health page cites the WHO 2020 guidance and Dunstan 2012 and makes no medical claims. Synthetic and replay data get banners and are never saved.

### Timed run state machine

```
Start ─▶ lead_in 5s (wall) ─▶ empty_baseline 1+20s (packet) ─▶ grace 5s ─▶ walking 1+15s
      ─▶ transition 3s ─▶ standing_still 1+20s ─▶ transition 3s ─▶ sitting 1+20s ─▶ compute
```

`CalibrationSession` only moves forward on engine frames or on `state()` polls. A waiting phase therefore depends on the UI's 500 ms poll, which runs on every page while a run is active. Each new cue calls `speechSynthesis.cancel()` before speaking. The 3 s transition cue ("Stop walking and stand still. Recording starts in 3 seconds.") takes about as long to say as the transition lasts, so the next cue can cut off its last words (likely, cosmetic). The beep still marks the boundary.

### Posture model and live classification

Training uses only quality-OK frames. At runtime `PostureClassifier` classifies only frames whose motion score is below the movement threshold, averaging a 3 s window, with a 5 s hold or a 2 s confirm after movement. That threshold is `quiet_p95 + 0.5 * (walk_median - quiet_p95)`, where `quiet_p95` uses the empty room and standing still but not sitting. The only sitting-related warning fires when the sitting median exceeds `rapid`. Someone who types or shifts in the chair more than they did during the 20 s still-sitting step goes to `moving` after 1 s (`MOVING_CONFIRM_S`). `UPRIGHT_STATES` treats moving as upright, so that time counts toward stand hours and can end a sitting streak through `stand_break_s` (likely). This doesn't block calibration or testing, but it is the most probable source of inflated upright numbers in real use. It is worth watching on the Sensor page's motion chart during the first live test.

### History during calibration

`PostureService._on_frame` runs for every frame whatever the calibration state is. During a live calibration the user walks, stands and sits for about 95 s. Those minutes are classified under the previously active model (or as unknown/moving without one) and saved to `posture.sqlite3` as real bouts (confirmed). This is minor for a single test session, but it accumulates if the user recalibrates often.

### Dashboard calibration page

The pre-run plan table, the form validation (which mirrors the server's ranges and placement regex) and the result panel all work: the panel shows the self-check with its "optimistic, not validated accuracy" caveat, plus any warnings. During a run, `renderRun` keeps calling `renderPlanTable` with the current index, but the table is inside the hidden `cal-setup` card. The run card shows the phase title, countdown, instruction, next cue and a progress bar with the time left out of 1 min 35 s, so the user still sees the total, just not the per-phase list (confirmed, cosmetic).

### Test coverage

Covered: the defaults producing 95 s, an auto run on a fake clock with grace/transition ordering, a failed step stopping the run, cancel during a wait, posture-model separation and the identical-profile warning, format-1 calibration back-compat, the synthetic/real separation rules, the posture API shapes and validation, a `desk_day` run with a synthetic calibration, and static UI structure and minimal-style rules. Not tested: browser audio and speech, the live serial path, the interaction between calibration and posture-history persistence, and seated motion above the movement threshold.
